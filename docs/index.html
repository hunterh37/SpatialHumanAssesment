A one-minute setup, one question at a time

Clickable prototype built from the Dusk design spec v1.0: charcoal glass over the sunset scene, cream text, a single peach button for the next step. Answer and press Continue, or jump to any step below. Names and numbers are sample data.

What we collect, and why

ScreenSaved asStatusWhy we ask
First nameNot savedThis visit onlyGreets the player during setup. Cleared when the session ends, so results stay code-only.
Ageparticipant.age_yearsRequiredMovement age starts from chronological age, N(age, 9²), and is compared with age norms.
Sexparticipant.sexOptionalNorms differ by sex. Values: female, male, other, unspecified.
Heightparticipant.height_cmNew fieldSets reach distances in Spark and Reach and Grab to the player's size.
Weightparticipant.weight_kgNew fieldSkippable. Not used by ScoreKit today; useful for clinic records.

Standing or seatedparticipant.postureNew fieldSafety. Seated play skips Reach and Grab and Hole in the Wall.
(automatic)participant.codeRequiredRandom code, for example SA-4821. The only identity that is saved.

Notes for the team

Names. The Dusk spec says never store names, only participant codes. This flow asks for a first name because it was requested, uses it only to greet the player during setup, and never writes it to the session. Drop the screen if the team wants no name at all.

Schema. Height, weight and posture are new optional fields on participant. Adding them means bumping the session schema version (repo rule).

Spec checks. Dusk tokens only. Signal colors aren't used for decoration, apart from gold on the current progress dot, which the spec allows. One primary button per screen, every control at least 60 pt, "movement age" wording, no exclamation marks, Reduce Motion respected.
